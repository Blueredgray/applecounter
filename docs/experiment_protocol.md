# Экспериментальный протокол

## Назначение датасетов

- **MinneApple**: обучение и независимая оценка детектора на официальном val-сплите. Видео, собранное из train-изображений, не используется для оценки обобщения. Для оценки трекинга нужны постоянные GT ID; COCO annotation ID такими ID не являются.
- **T1 (Zenodo 7384297)**: отдельный MOT-бенчмарк. Не относится к VideoFruitCounting и не смешивается с его 16 видео.
- **VideoFruitCounting (VFC)**: 16 видео, две камеры, четыре ряда и две стороны. Основная единица результата — один из 21 stretch. SFRAME содержит кадры маркеров границ, а не GT числа яблок. Оценка абсолютной ошибки возможна только на вручную размеченном контрольном подмножестве.

## Методические ограничения

- `n_double_count_events` — диагностика повторного события одного внутреннего ID, а не оценка повторного подсчёта физических яблок.
- Число созданных треков не равно числу яблок. Один плод может получить несколько ID, а один ошибочный ID может объединять несколько плодов.
- Эвристическое деление stretch по среднему размеру боксов не является обнаружением отдельных деревьев. Для результатов по деревьям нужны размеченные границы деревьев.
- Прогноз массы `N × mean_mass / visibility` без полевой калибровки является иллюстративной оценкой, а не валидированным прогнозом урожая.

## Матрица

Детекторы: HSV, YOLOv8n@640, YOLO26s@1280. Трекеры: BoT-SORT и DeepSORT; ByteTrack добавляется через тот же интерфейс и тот же кэш детекций.

1. Для каждого видео и детектора один раз создать кэш детекций.
2. Для каждого трекера использовать идентичный кэш, порядок кадров и предобработку.
3. Сохранить сырые MOT-результаты до фильтрации и объединения фрагментов.
4. Не выполнять post-hoc merge в основном сравнении.
5. Для VFC применять `trees.assignment=vfc_reference` — один общий механизм назначения stretch по маркерам ко всем методам; `median_frame` использовать только как отдельную диагностику.
6. Настраивать параметры только на validation-подмножестве; контрольное подмножество не использовать для настройки.

## Метрики

- Детекция: AP50 (и AP50–95 при использовании стандартного валидатора), precision, recall, FP/FN, MAE числа детекций на изображение.
- Трекинг: MOTA, IDF1, IDSW через MOT-совместимую библиотеку; HOTA добавляется при наличии TrackEval.
- Подсчёт: MAE, RMSE, bias, MAPE и относительная ошибка итогового счёта по stretch/дереву и по видео.
- Производительность: время детекции и трекинга раздельно, число обработанных кадров, FPS.

## Воспроизводимость

Каждый новый прогон сохраняет полный конфиг, версии пакетов, путь и SHA-256 весов, SHA-256 входного видео/кэша, параметры предобработки и Git commit. Готовность определяется не наличием одного `summary.json`, а валидным манифестом с успешным статусом и совпадающим отпечатком конфигурации.

## Минимальный допустимый эксперимент

1. MinneApple val: HSV, YOLOv8n, YOLO26s.
2. T1: одинаковые детекции для всех трекеров, стандартные MOT-метрики.
3. VFC: короткий контрольный набор с ручным count GT, счёт по 21 stretch.
4. Полные 16 видео только после успешной проверки контрольного набора.
5. Прогноз массы публиковать как валидированный только при наличии независимого полевого контроля count/mass.
